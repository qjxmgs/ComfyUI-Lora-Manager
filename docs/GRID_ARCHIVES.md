# LoRA grid archives

The grouped LoRA Loader toolbar includes an archive selector, Save, Restore and
Manage buttons. Archives belong to the current LoRA Manager settings directory
and are shared by nodes and workflows. Each node retains its own selected archive.

## Using archives

- An unassociated grid displays `* Untitled`. Save asks for a name and a secondary
  category; categories can be created in that dialog. Save subsequently updates
  the associated archive. Manage also offers **Save current grid as**.
- An asterisk indicates that the grid differs from its saved archive. Switching
  with changes offers Save and switch, Discard and switch, or Cancel.
- Restore loads the current archive's latest saved grid. Restore and switching
  participate in ComfyUI node undo/redo, including node dimensions and association.
- The manager has primary categories, secondary categories, archives and a fixed
  preview panel. Hovering or focusing an archive updates the preview without loading
  it. Clicking its name loads it; Edit changes its name/category without loading it.
- Drag rows to reorder siblings. Edit a secondary category to move it to another
  primary category. Deleting a nonempty category requires a destination at the same
  level. Conflicting names must be resolved first. Default categories are protected.
- The preview shows the saved image and enabled LoRAs, with Model and CLIP strengths
  overlaid at the bottom. Disabled groups are excluded. Missing local models are
  marked, not silently removed from the archive.
- Choose, drop or paste a PNG, JPEG or WebP image (at most 20 MiB / 40 megapixels).
  The server stores a WebP preview with a longest side of at most 1024 pixels.
  Images can be replaced or removed without marking the grid as modified.

## Snapshot and workflow compatibility

Snapshots contain grid dimensions; group order, names, colors, modes, sorting and
pause state; all LoRAs with their group, order, strengths, activation, locks and
CLIP expansion; and node width/height. Node position, connections, title, Anima
mode and global preferences are not part of the archive.

`node.properties.lmGridArchiveId` stores the association. Existing workflow data
remains self-contained: opening a workflow restores its own grid, then compares
it with the associated archive. It never automatically loads a global archive.
Deleting an archive detaches the association while preserving the node's grid.
Selection, focus, scroll position and numeric formatting do not mark a grid dirty.

The shared client publishes archive list changes within the page and refreshes
on page focus or opening the selector/manager. Other nodes' grids are not changed.

## Persistence and API

Storage is under the resolved settings directory:

```text
grid_archives/
  library.json
  images/<generated-id>.webp
```

The directory is included in portable/settings-directory migration. It contains
no model sidecars and does not use the Recipe library. Writes use a process-wide
lock and atomic file replacement. Corrupt libraries are reported without being
overwritten. Preview filenames are generated by the service, not supplied paths.

Both ComfyUI plugin and standalone modes register `/api/lm/grid-archives`:

| Method | Suffix | Purpose |
| --- | --- | --- |
| GET | (empty) | Read the library and revision |
| POST | `/categories`, `/archives` | Create an item |
| PATCH | `/categories/{id}`, `/archives/{id}` | Edit an item; archive snapshot is optional |
| DELETE | `/categories/{id}`, `/archives/{id}` | Delete; nonempty categories require `destinationId` |
| PATCH | `/{categories\|archives}/reorder` | Supply every sibling ID in `ids`, plus `parentId` or `categoryId` |
| GET | `/archives/{id}/image` | Read the current preview |
| POST | `/archives/{id}/image` | Upload image bytes |
| DELETE | `/archives/{id}/image` | Remove the preview |

JSON mutations require the library `revision`; image mutations require that
revision in `If-Match`. An archive edit may also supply `archiveRevision` to guard
a form retained across category creation or background refresh. Stale revisions
return HTTP 409 with `error: "conflict"`, retaining local node changes. Mutations
return the updated library; creation additionally returns `resultId`.

The library is version 1. Snapshots are `{version: 1, groupConfig, entries,
nodeSize: [width, height]}`; `groupConfig` uses the existing group version 2 schema.
The manager position and size are browser-local preferences, separate from grids.

## Validation

Automated tests cover persistence and corruption, concurrent revisions, category
moves and ordering, image processing and validation, workflow compatibility,
dirty-state detection, switching, restore and widget integration. UI geometry,
theme appearance, real pointer behavior and ComfyUI undo/redo are checked manually
in the installed runtime; unit tests do not establish visual acceptance.
